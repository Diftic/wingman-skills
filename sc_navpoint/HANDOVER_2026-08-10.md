## 3. What changed, and why it is shaped this way

### A waypoint is now an address, not a name

A newly marked waypoint stores the exact `Zone: Root Pos:` triple, the
`SolarSystem` row, and every nested row above them, from one accepted capture.
Root is the long-range address. The nested rows are stored in observed screen
order with their own depths.

`coordinate_stack.py` is pure: no Wingman runtime, no OCR, no database, no
logging. **Every `raw_name` and `raw` value in a stack can be deleted or
scrambled without changing a routing decision**, and
`test_coordinate_stack_router` proves it by randomising them.

### The behaviour change that matters

**A Pyro 3 surface can be marked at all now.** Pyro names bodies without an
`OOC_` prefix, so the legacy parser refuses that capture through `body_scale`,
correctly: emitting a system-frame position for a player standing on a rotating
body is the 2026-07-11 failure. That gate is **untouched**.
`payload_from_rows` still returns `None` for those rows and no `local` or
`system` waypoint can be built from them.

The coordinate stack reads the same three rows, needs no name, and carries the
capture on its own. The dispatch between the two lives in a **new** function,
`overlay_fields.capture_payload`, which `main.py` calls. That is why zero
existing safety assertions moved: the legacy parser keeps its exact contract and
its roughly forty test call sites.

### The two ceilings

`LOCAL_TRACKING_MAX_M = 3_000_000.0`, a product invariant and deliberately not a
YAML property. Root is computed first and unconditionally. **Equality belongs to
Root at both ceilings**; a `<` turned `<=` is mutation-proven to fail a test.
There is no hysteresis band.

Note that this ceiling does **not** rest on the disputed 15,000 km numbers in
`ledger/LEDGER.md`. It is a separate quantity, and the body/container scale
window is never consulted by a stack route.

### Presentation

- ROOT APPROACH says "coarse" out loud, because a rotating surface target's
  saved Root position is deliberately stale within a body-sized envelope.
- **Arrival can never be announced from a Root distance**, even at zero.
- The ring draws **no** bubble for a stack target in either mode and says
  `NO BEARING`. Enabling local tracking buys distance and arrival, not a
  bearing: the direction convention is still uncalibrated
  (`navigation.SPACE_DIRECTION_CALIBRATED = False`).
- The HUD page shows `ROOT APPROACH (coarse)` or `LOCAL`, computed server-side
  by the same pure selector, because two implementations of a routing rule
  cannot be kept in step.
- No new tool, no new custom property, no coordinates, labels, JSON or internal
  thresholds in any model-visible payload. Token-neutral.

### Schema v4, additive

Five columns: `coordinate_schema`, `root_x`, `root_y`, `root_z`,
`coordinate_stack`. A v2 or v3 database upgrades in **one** step off a single
column list, so a user who skipped the v3 build lands on the identical shape.

Legacy rows keep every field they had and gain `coordinate_schema = 0` with a
NULL Root. **NULL Root is meaningful**: no Root position was ever captured for
them, and synthesising one from a body-fixed coordinate is mutation-proven to
fail a test. A corrupt `coordinate_stack` column leaves the row listable,
renamable and deletable, and refuses only navigation.

## 5. What is NOT done, and what it needs

### The evidence gate, which is the whole rollout

`LOCAL_TRACKING_ENABLED = False`.

"The row immediately before SolarSystem is the body or area frame" is an
**implementation hypothesis, not a measured identity**. It has never been
checked against paired captures across two different ships, a landed ship
against standing outside it, or a jump point. If it selects a **movable**
container, a waypoint would track whoever owns that ship.

The full matrix is in the plan's "Local-candidate evidence gate" section. It
needs, at minimum: on foot on a moon or planet; seated in a landed ship then
outside it at the same site; two different ships near one another; an asteroid
base interior; an orbital marker pair near 1.5 Mm; deep space with no body row;
a jump point; and Stanton and Pyro examples including one with no `OOC_` row.

**Repeated captures from one stationary pose are not independent evidence.**

If the candidate selects a movable frame, stop the rollout, leave the flag off,
append the evidence to the ledger, and ask for a revised invariant. Do not
substitute a row-number, prefix, name or scale heuristic; all four are in
`ledger/REFUTED.md`.

### Wave 5, in order

1. Replay the retained lossless corpus through `overlay_fields.stack_from_rows`.
   Do not validate from OCR text logs alone.
2. Run the paired-capture matrix above.
3. Append measured facts to `ledger/LEDGER.md`, refutations to `REFUTED.md`,
   capture provenance to `CORPUS.md`.
4. Only then request approval for a supervised live flight. Live testing must
   not install an unreleased dev tree.

## 7. Corrections and findings from this session

Recorded rather than smoothed over, because a report that silently repairs
itself is harder to trust than one that shows its working.

**Two defects in my own new code, found by my own tests:**

- `distance_m` used a naive sum of squares and **overflowed** on an extreme
  coordinate, which a corrupt `coordinate_stack` column is enough to reach, on
  the poll thread where a raise is a dead navigation loop rather than a visible
  error. Now `math.dist`, which is built on `hypot`.
- The mutation harness gave **different verdicts on consecutive runs**. Bytecode
  caching keys on mtime and size, and a mutation applied inside one filesystem
  timestamp left a stale `.pyc`. Fixed with `PYTHONDONTWRITEBYTECODE` plus a
  cache sweep before each run. **Four "escapes" in the first run were that bug,
  not real gaps.** An unstable harness reads exactly like a weak test, and I
  nearly rewrote four good tests to chase it.

**Two mutations I wrote escaped for a real reason rather than a bad test.** A
damaged coordinate cell is refused by **two independent layers**, the row regex
and the unit conversion, so relaxing either alone changes nothing. Each layer now
has its own test, plus a both-layers mutation for the end-to-end outcome.

**Two mutations were removed as unprovable, which is a finding rather than a
gap.** The `stack_decision is None` guards on the legacy frame-id and cross-body
gates cannot be shown to matter: a stack row carries an empty `frame_id` and an
empty `body`, so those gates cannot fire on one anyway. The same is true of the
stack branch in `navigation.ring_deflection`, since a stack target has neither a
body nor a system frame. All three stay for explicitness. **None of them is what
stops the failure**, and a future reader should not mistake them for protection.

**One over-claim in a comment, corrected before it shipped.** I first wrote that
the `$` anchor on the coordinate-tail regex is what rejects a truncated row. It
is not: the requirement of **three** tokens does that. The `$` does the narrower
job of refusing anything trailing the third component. The comment now says so.
